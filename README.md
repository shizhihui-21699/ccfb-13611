# eclipseguard

点对点网络中邻居发现与邻居表管理的抗 eclipse（日食/包围）攻击实现与仿真框架。
同一套网络条件下对比改造前的朴素邻居表与加固邻居表，量化“攻击者控制大量
地址时，目标节点被包围的概率”。

## 目录结构

```
.
├── netaddr/          仿真地址与 /16 分组抽象
├── table/
│   ├── table.go      公共类型、决策枚举、NeighborTable 接口
│   ├── naive.go      改造前：单表 + 随机淘汰 + 重启清空（基线）
│   ├── hardened.go   改造后：双表/组上限/锚点/观察期/保护性淘汰/重启恢复
│   └── anchor.go     锚点持久化（内存实现 + 0600 落盘实现）
├── sim/
│   ├── world.go      上千节点网络：地址池、分层抽样、churn、攻击洪水
│   └── engine.go     试验主循环、重启宽限期、测量与汇总
├── stats/            多次试验聚合、Wilson 置信区间、CSV 输出
├── cmd/eclipsesim/   命令行入口（7 个攻击场景 × 2 策略）
├── DESIGN.md         威胁模型与六层防御的完整设计说明
└── results/          运行后生成的 CSV
```

## 快速开始

```bash
go test ./...                       # 单元测试（含关键安全不变量断言）
go test -race ./...                 # 竞态检测
go run ./cmd/eclipsesim -quick      # 30 次试验冒烟，约 10 秒
go run ./cmd/eclipsesim -trials 200 # 完整实验，约 1 分钟
```

可选参数：`-trials N`、`-quick`、`-outdir DIR`、`-seed S`。

## 实验结果（每场景 200 次独立试验，Wilson 95% 置信区间）

网络：1000 诚实节点 / 40 个 /16 组；攻击窗口 250 tick；洪水 16 地址/tick；
攻击中第 120 tick 重启，宽限期 3 tick。

| 场景 | 策略 | 攻击地址数 | P(100% 包围) | P(≥75% 包围) | P(重启后 100%) | 窗口峰值攻击者占比 | 峰值单组占比 | 平均活跃邻居 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 集中攻击 / 4 组 | naive | 500–4000 | **100%** | **100%** | **100%** | 100% | 45–47% | 31.9 |
| 集中攻击 / 4 组 | hardened | 500–4000 | **0%** [0,1.9%] | **0%** | **0%** | 7–8% | 12% | 30.9 |
| 分散攻击 / 32 组 | naive | 1000–2000 | **100%** | **100%** | **100%** | 100% | 18% | 31.9 |
| 分散攻击 / 32 组 | hardened | 1000–2000 | **0%** [0,1.9%] | **0%** | **0%** | ~49%* | 12% | 28.1 |
| 关闭重启对照 | naive | 2000 | 15.0% | 100% | — | 96.9% | 46% | 32.0 |
| 关闭重启对照 | hardened | 2000 | **0%** | **0%** | — | 0% | 6% | 32.0 |

\* 分散攻击下攻击者最多成为“少数派邻居”（理论上界 32 组 × 4 槽 / 32 容量
= 50%，实测峰值 ~49%、均值 ~25%），永远无法达到多数，节点不会被隔离；
这正是“能当邻居”和“能包围”的区别。组上限把单组影响力钉死在 12%。

### 结论

1. **朴素表在所有场景必然失守**：只要攻击者持续供给地址，窗口内被
   ≥75% 包围的概率为 100%；重启窗口内 100% 被完全包围。
2. **加固表在所有场景零包围**：200 次试验中 100% 与 ≥75% 包围均未发生
   （置信上界 1.9%），且结果与攻击者地址总量（500→4000）基本无关——
   防御基于结构性上界而非概率运气。
3. **重启持久化锚点的独立贡献**：关闭重启的对照中加固表峰值攻击者占比
   为 0%；开启重启场景下依然 0%，证明锚点重建挡住了重启窗口攻击。
4. **不牺牲正常更替**：加固表平均活跃邻居 28–32（容量 32），churn 产生
   的空槽正常填充，真实新邻居经过 8 tick 观察期即可转正。

## 指标说明

- `P(eclip 100%) / P(eclip>=75%)`：攻击窗口内活跃邻居（tried 区）攻击者
  占比曾达到阈值的试验比例；
- `P(rst ...)`：重启后首个测量帧的同类指标，衡量重启窗口针对性攻击；
- `peak evil`：窗口内攻击者占比峰值的跨试验均值；
- `peak 1grp`：窗口内单个 /16 组最大占比峰值的均值，直接反映组上限效果；
- `mean act`：窗口内平均活跃邻居数，可用性指标。

完整数值（含半包围概率、各置信区间边界）见 `results/eclipse_results.csv`。
设计原理与参数取舍见 [DESIGN.md](DESIGN.md)。
